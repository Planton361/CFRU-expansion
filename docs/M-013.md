  `CheckBagHasSpace` / `AddBagItem` at `0809A000` / `0809A084`.
  The target retains their pret single-stack capacity contract (999), with
  no replacement of either function. NatDex's free-space summation is not
  copied into CFRU: the target capacity predicate agrees with its own add API.

## Bounded change

Move the existing Premier branch before the custom table, decrease the reward
until `CheckBagHasSpace` accepts it, add once, and always exit the ball path.
Zero capacity/add failure returns without trying custom ball rewards. Use
16-bit purchase/reward quantities to avoid truncating task data. Both existing
feature flags stay enabled and unchanged. Custom non-ball table entries and
their callback logic are preserved. Disabling the multi-Premier compile flag
retains legacy custom-table behavior; that is not the pilot profile.

The M-009 insertion preflight previously rejected every later src change.
Its allowlist now admits only this callback (the rest of item.c is compared
to its prior baseline), this test script and harness. All frame, scanner,
hook and insertion guards remain. No DPE, UPR, shop refactor, inventory,
price, field-item or Move Reminder change.
