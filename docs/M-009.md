## Scanner and transient cache

`src/hidden_item_sparkle.c` scans only current-map BG events. It excludes
non-hidden events, ITEM_NONE (including the item-zero coin encoding), underfoot
events, collected flags and positions outside camera focus +/-7 X and +/-5 Y.
It uses raw BG map coordinates for `FLDEFF_SPARKLE`, whose existing creator
adds the map offset. It does not scan neighboring maps or change pickup logic.
Randomized item identity does not alter the slot/collection-flag identity.

The two tiny source helpers not exposed by current CFRU, `GetCameraFocusCoords`
and `GetHiddenItemAttr`, are copied semantically as local functions from the
reference fieldmap/field-specials source. Focus is saved map position plus
MAP_OFFSET, not the player's destination. The attribute helper decodes the
existing packed item/flag-offset/quantity/underfoot fields. No guessed binding
is used. Collected state is `FlagGet(FLAG_HIDDEN_ITEMS_START + flagOffset)`.

No supported hidden-sparkle flag exists in the inspected tracked CFRU config
or flag headers. The private pilot is therefore enabled by default. No flag,
save format, Itemfinder mode, or UPR-FVX toggle/dependency is added.

Cyan's per-BG-event cooldown value is 16: after a spawn, 16 eligible frames
decrement that event's counter and the following eligible frame can spawn
again. Offscreen/collected/excluded events do not decrement their counters.

The pinned source census is 426 Cyan maps and 425 pret maps. Both peak at
36 BG events, in `CeladonCity_GameCorner`. Current CFRU map overlays preserve
BG pointers/counts; those templates and the previous overlay implementation
are locked unchanged by the acceptance checker. Capacity is 36, indexed by
BG-event index, including non-hidden entries. Future oversized tables suppress
the feature until the capacity contract is reviewed.

**CFRU adaptation:** its linker places ordinary .bss in ROM, so copying Cyan's
writable static cache would be invalid. One no-op task supplies existing
transient RAM. Two map-ID bytes plus 36 packed five-bit cooldowns occupy 25
bytes of its 32-byte data array. A compile-time bound includes the helper's
extra byte read. No new RAM address, heap allocation, save field, persistent
pointer, or sprite owner is needed. The task callback never scans or spawns;
all such work is at the exact canonical frame tail.

The cache resets on group/number changes. `ResetTasks` invalidates it on
reload paths; the next valid frame discovers or recreates it. Empty, null or
oversized BG tables release the cache task, including A -> empty B -> A
connected-map round trips. Task creation checks capacity first and leaves a
spare slot; if unavailable, the feature suppresses itself. The vanilla
CreateTask exhaustion return must not be mistaken for ownership of task zero.
This uses one task slot; task-pressure testing remains part of runtime review.

## Effect and lifecycle limits

The existing CFRU `FLDEFF_SPARKLE` implementation, palette selection, sprite
template and callback remain unchanged. There are no custom persistent
sprites, manual sprite-slot searches, palette allocation, effect-list cleanup,
pickup-script modifications, or revived transition/resume spawn tasks.

Cyan's small-sparkle source also has a one-callback visibility delay and an
explicit palette-slot choice. Those effect changes are **not** ported: the
approved scanner uses CFRU's existing effect. Visual timing and palette
compatibility are therefore runtime gates, not inferred equivalence.

| Lifecycle | Source/host evidence | Required runtime acceptance |
|---|---|---|
| Normal movement / standing | Repeated scans at frame tail; independent counters tested | Stable marks while standing and walking, correct camera alignment |
| Second item enters view | Forest coordinate test spawns each independently | Reach both Forest items; neither starves or disappears permanently |
| Item leaves view | No new effects outside the rectangle | Existing one-shot ends naturally; no lasting offscreen/stray marker |
| Connected transitions | Map identity invalidates cache, including empty-map round trip | No old-map sparkle at an unrelated position after camera/map change |
| Warp / return / reload | Reference `ResumeMap` clears tasks, sprites and effect list; host reset simulation reconstructs cache | Door/warp/re-entry and same-map reload work without stale state |
| Start Menu / Save dialog | Existing frame may keep running while controls are locked | Open/close/cancel/save without flicker, freezes, unexpected effects |
| Party / Bag / Options | Reference field return reconstructs tasks/graphics | Every return restores correct markers and palette/camera state |
| Pickup while visible | Set flag suppresses future spawns; existing effect is not forcibly killed | Transient sparkle finishes, then stays absent; bag-full retains marker |
| Renewable flags | Current flags are re-read; cleared flag allows later respawn | M-004 renewal still makes eligible markers reappear |
| Multiple effects / pressure | 36 counters and task saturation tested with engine doubles | Sprite exhaustion, DexNav/other effects, NPC/player palettes and task-heavy scripts remain healthy |
| Quest Log / fades | Wrappers untouched; arrival call/order restored | Map arrivals, Quest Log where applicable, fades, load/return and M-001–M-008 smoke remain healthy |

Host tests do not emulate sprite lifetime, VBlank, camera pixel interpolation,
palette allocation, engine sprite exhaustion or actual menu transitions.
Existing one-shot effects are not immediately removed on pickup or when
leaving range. They finish through the engine's transient lifecycle. Allocation
failure and shared field-effect bookkeeping are inherited engine risks and
must not be promoted to runtime PASS from these tests.

- checks the exact eleven-call body, aliases and untouched wrappers;
- checks scanner filters, focus API, raw map arguments, cooldown and map reset;
